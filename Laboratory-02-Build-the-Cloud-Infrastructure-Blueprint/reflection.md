# Mission 2 Reflection

## 1. Which cloud infrastructure component do you think is the most important? Why?

I think compute resources are one of the most important cloud infrastructure components because they provide the processing power needed to run applications and services. Without CPU and memory, the other infrastructure resources would not be able to support running workloads effectively. However, compute also needs storage and networking to work properly as part of a complete cloud system.

## 2. How does Linux support cloud computing?

Linux supports cloud computing by providing a stable and flexible operating system for servers and cloud environments. It also provides powerful command-line tools that allow administrators and cloud engineers to inspect, configure, and manage server resources. In this activity, I used Linux commands to investigate the CPU, memory, storage, network, operating system, and mounted filesystems.

## 3. Why is technical documentation important before deploying infrastructure?

Technical documentation is important because it provides a clear record of the resources, configurations, and decisions involved in an infrastructure design. It helps engineers understand the environment before deployment and makes troubleshooting easier when problems occur. Good documentation also helps teams communicate and maintain systems more effectively.

## 4. What new skills did you learn during this laboratory activity?

I learned how to investigate a Linux cloud environment using commands such as `lscpu`, `free -h`, `df -h`, `findmnt`, and `ip addr show`. I also learned how to interpret basic server information and identify compute, storage, networking, and operating system resources. In addition, I improved my Markdown and GitHub documentation skills.

## 5. How has your GitHub portfolio improved after completing this mission?

My GitHub portfolio became more organized and more useful as a record of my Cloud Computing activities. I added a complete laboratory folder containing technical documentation, infrastructure findings, cloud provider comparisons, screenshots, and a cloud architecture diagram. This activity also helped me understand how to document technical work professionally and keep evidence of my learning in one place.
